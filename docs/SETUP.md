## AMD GPU: use ./run.sh instead of `uv sync` / `uv run`

If you set up the local AMD GPU runtime (below), **do not run `uv sync` or `uv run` directly** once the initial install is done. `llama-cpp-python` is a plain dependency in `pyproject.toml` with no build flags, so any `uv sync` (including the implicit one `uv run` does by default) silently reinstalls a CPU-only build and discards the GPU backend (Vulkan on openSUSE, HIP on Arch) compiled by the installer — with no error.

Instead, start the app with:

```bash
./run.sh
```

It launches `main.py` directly through the venv's own Python (never through `uv run`), and if it detects the GPU backend `.so` is missing (e.g. because something ran `uv sync` since the last start), it recompiles `llama-cpp-python` with the right flags for your distro before booting.

A simpler `./start.sh` is also available — it seeds a default `model-runtime-config.json` in the vault if missing (temperature, top_p, penalties) and runs `uv run python main.py`. Prefer `run.sh` once you've compiled a GPU backend; `start.sh` doesn't protect it from being silently discarded.

## AMD ROCm Setup

For an AMD-only machine, use the installer matching your distro:

```bash
./installer-arch.sh       # Arch Linux and derivatives (pacman)
./installer-opensuse.sh   # openSUSE Tumbleweed (zypper)
```

Both scripts:

- Install the build toolchain, ROCm runtime, and `uv`.
- Detect `AMD_GPU_TARGET` using `rocminfo` (or respect your exported value).
- Persist ROCm environment variables (`ROCM_PATH`, `HIP_PATH`, `HSA_OVERRIDE_GFX_VERSION`, `LD_LIBRARY_PATH`) for `bash` and `fish`.
- Install `torch`/`torchvision`/`sentence-transformers` from the prebuilt ROCm wheel index, scoped to the project's `.venv` (nothing is installed into the system Python).
- Compile `llama-cpp-python` from source, scoped to the same `.venv`, and verify it reports GPU offload support before finishing.

They differ only in the `llama-cpp-python` GPU backend, because of how each distro packages ROCm:

- **Arch** (`installer-arch.sh`): compiles with the native HIP backend (`-DGGML_HIP=ON`), since `rocm-hip-sdk` bundles hipBLAS/rocBLAS.
- **openSUSE** (`installer-opensuse.sh`): compiles with the Vulkan backend (`-DGGML_VULKAN=ON`), since Tumbleweed does not package hipBLAS/rocBLAS. Vulkan performs comparably on RDNA3 and needs no ROCm math libraries — `vulkan-devel` and `shaderc` (for `glslc`) are enough.

Only the `llama-cpp-python` build differs; `torch`/`sentence-transformers` still run on ROCm on both distros, since PyPI ships self-contained ROCm wheels that don't depend on system hipBLAS.

If you need to override defaults on either script:

```bash
AMD_GPU_TARGET=gfx1100 HSA_OVERRIDE_GFX_VERSION=11.0.0 ./installer-opensuse.sh
```

If you'd rather use an embedding model you already have pulled in a local Ollama daemon instead of installing `sentence-transformers`, skip that step and set `OLLAMA_EMBEDDING_MODEL` (see [Environment Variables](#environment-variables) below).

## API Reference

The app registers **94 HTTP routes plus 1 WebSocket** across 7 modules at startup (see `app/core/module_registry.py`, `dump_registered_routes`); the same inventory is browsable live at [`/admin/routes`](#admin-panel). Rather than transcribing every route, here's what each module's API surface is for — the full interactive reference (every path, method, and request/response schema) is auto-generated by FastAPI and always in sync with the code:

- **[`/docs`](http://localhost:8000/docs)** — Swagger UI, try-it-out included.
- **[`/redoc`](http://localhost:8000/redoc)** — ReDoc, read-only reference.
- **[`/openapi.json`](http://localhost:8000/openapi.json)** — raw OpenAPI schema.

| Module | Base path | Routes | What it exposes |
|---|---|---|---|
| `knowledge` | `/api/knowledge/*` | 25 | Document ingestion (raw text, file upload with a streamed job-progress channel, tag/delete), engram CRUD (incl. bulk CSV import, memory/affective-state stats), identity resolution, and context building (route → pack → prompt → graph). |
| `interaction` | `/api/interaction/*` + `/ws/chat` | 22 + WS | Conversation session management (list, restore, rewind, delete), message CRUD, HTTP streaming and the real-time chat WebSocket, plus nested admin context-trace and "idea clip" endpoints. |
| `models` | `/api/models/*` | 16 | Model catalog/selection, inference runtime status, Ollama model listing, text/vision smoke tests, runtime config, generation-profile CRUD, and a restart-with-progress-stream endpoint. |
| `operations` | `/api/operations/*` | 13 | Saga CRUD (create/list/patch/delete acts), saga orchestration (commands, debate, consistency check, retcon, next-context window), system status, and the audit log. |
| `storage` | `/api/storage/*` | 11 | Vault overview and file listings (public/uploads/vault), per-session chat asset management, engram content/avatar upload with digesting, and vault ingestion. |
| `workshop` | `/api/workshop/*` | 6 | Workshop session CRUD (create/list/get/close/delete) and promotion to the general knowledge base. |
| `platform` | `/api/platform/*` | 1 | A single `/health` route that aggregates module health over the internal event bus rather than direct HTTP calls. |

## Environment Variables

`.env.example` has 61 variables in 8 groups (see the file for the full list with inline defaults and comments — this section only calls out what each group controls and the variables you're most likely to touch):

1. **API/server** — app name, host/port, admin local-only lock, remote-admin allowlist, rate limiting, ban list.
2. **Conversation governance** — guard/sanitize/timeout/telemetry toggles, immersive mode, raw output mode, per-turn RAG match limit.
3. **Model storage/discovery** — `AI_MODELS_DIR`, `VAULT_DIR`.
4. **Text inference runtime** — `LLM_PROVIDER` (local/lmstudio/ollama), model paths, context size, per-provider timeouts.
5. **Embedding runtime** — `OLLAMA_EMBEDDING_BASE_URL` / `OLLAMA_EMBEDDING_MODEL` (real embeddings via a local Ollama daemon), `APP_EMBEDDING_MODEL_DIR` (local `sentence-transformers` fallback), `APP_TOKENIZER_MODEL_PATH` (GGUF used vocab-only for real-token chunking).
6. **Vision inference runtime** — same provider options as text, scoped to vision models.
7. **Generation tuning** — `min_p`, repeat/presence/frequency penalty, seed (overridable at runtime via `model-runtime-config.json`, no restart needed).
8. **Database/persistence** — `DATABASE_URL`, echo, auto-schema-on-start, pool sizing, plus `VECTOR_DB_USER`/`VECTOR_DB_PASSWORD`/`VECTOR_DB_NAME` (read automatically by `docker-compose.yml` if you run the optional PostgreSQL/`pgvector` container).

## Deployment

The app itself runs **natively** (not containerized) via `uv` + Python 3.13, with `llama-cpp-python` compiled per-machine against the local GPU — see [AMD ROCm Setup](#amd-rocm-setup) above for why. `Dockerfile` + `docker-compose.yml` only bring up the optional PostgreSQL + `pgvector` database (`vector_db` service, bound to `127.0.0.1:5433`); by default the app uses SQLite and needs no container at all.

## Testing

~102 tests in `test/` (flat, no per-module subfolders), covering PAD affective state, chat template rendering, embedding runtime fallback chain, engram directory, conversation governance, end-to-end integration between modules, knowledge retrieval, model catalog service, and real-time governance. Run with:

```bash
pytest
```

## Development conventions

`.agents/` holds a prescriptive coding-standard/architecture-convention set (Spanish) used to brief AI coding agents working on this repo — it describes an idealized module template, not necessarily this repo's exact current state. Useful if you're extending the codebase with an AI agent; not required reading to understand what the system does.

## Database

The default local database is SQLite under `.vault/rag2.sqlite3` when `DATABASE_URL` is empty.
Set `DATABASE_URL` to a PostgreSQL URL when you want server-backed persistence.

Core database wiring lives in `app/core/database/` and stays database-agnostic.

## Local Directories

- `.vault/` stores private runtime artifacts and should stay local.
- `.vault/public/` is mounted at `/public` for public static assets.
- `.vault/uploads/` is mounted at `/uploads` for local runtime uploads.
- `ai_models/` stores local model assets and caches.
